## BL-001 コーディング規範の assert の検証コマンドが、static_assert のための assert.h の取り込みも検出する

### 概要と問題点

- **現状の事象**: `app/general/docs/coding-guideline.md` の「異常状態の検出とプロセス終了」の「検証」にある検証コマンドは、「assert の使用と assert.h のインクルード (0 件であること)」として、`#include <assert.h>` も検出します。一方、同じ規範の「R2 制約を静的に検査する」は、静的アサートの表記を `static_assert` (`<assert.h>`) と定めています。そのため、規範に従って `static_assert` のために `<assert.h>` を取り込んだ箇所も検出され、2026-11-28 時点で `app/` 配下から 84 件が検出されます (例: `app/cplat/prod/include/cplat/compress/compress.h`、`app/struct-meta/prod/libsrc/struct_meta/meta/index.c`)。
- **本来あるべき姿**: 検証コマンドの検出が 0 件になるのは、`assert` マクロを使った場合に限られる状態です。`static_assert` のための `<assert.h>` の取り込みは検出しません。

### 経緯と見送り理由

- **摘出契機**: 案件 `261128-cjson-patch-marker` の回答の検証 (版 2 の Q-007 の作成) で、検査用のヘッダーが `<assert.h>` を取り込む場合の規範との整合を確認した際に発見しました。
- **今回の見送り理由**: 案件の範囲 (cJSON パッチ 0003 の適用のビルド時検査) の外であり、`app/general` の共通規範の変更にあたるためです。

### 影響範囲とリスク

- **影響対象**: `app/general/docs/coding-guideline.md` の検証コマンドと、それを使う確認作業です。
- **放置した場合のリスク**: 検証コマンドの結果が常に 0 件にならないため、`assert` の新たな使用が既存の検出結果に紛れて見落とされます。

### 推奨される対応策

- **恒久対応案**: 検証コマンドから `#include <assert.h>` の検出を除き、`assert` マクロの使用 (`assert(`) だけを検出する形へ改めます。`<assert.h>` を取り込むのに `static_assert` を使わない箇所を検出したい場合は、ファイル単位で `<assert.h>` の取り込みと `static_assert` の使用を突き合わせる検査を別に設けます。
